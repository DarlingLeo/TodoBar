# TodoBar 桌面待办清单

一个基于 Electron 的桌面端待办应用:常驻托盘、可贴边收纳、支持按日期浏览历史、邮件定时推送。

| 项目 | 说明 |
|---|---|
| 应用名 | 今日待办 TodoBar |
| 技术栈 | Electron(主进程 main.js + 渲染进程 renderer/) |
| 项目路径 | `todo-desktop/` |
| 数据文件 | `%APPDATA%\TodoBar\todos.json` |
| 备份文件 | `%APPDATA%\TodoBar\todos.json.bak`(每次启动自动备份) |
| 错误日志 | `%APPDATA%\TodoBar\error.log` |

---

## 一、运行方式

```bash
# 方式一:双击启动器
todo-desktop\启动TodoBar.bat

# 方式二:命令行
cd todo-desktop
env -u ELECTRON_RUN_AS_NODE ./node_modules/electron/dist/electron.exe --no-sandbox --disable-gpu .
```

> 说明:应用无边框透明窗口,点击右上角 ✕ 是隐藏到系统托盘(不退出);托盘图标右键菜单可退出。

## 二、功能总览

### 1. 待办管理

- **新增待办**:标题(≤200 字)+ **紧急程度(1-5 星)** + 预计完成日期/时间(均可选);回车或点「添加」。
- **完成待办**:点击待办前的方框 → 打勾 → 自动移入「已完成列表」,**完成时间 = 点击时刻**;再点一次可恢复为待办。
- **删除待办**:悬停条目点 🗑。
- **修改截止时间**:点击待办上的截止文字(如「截止 今天 17:00」「⚠ 已过期」「长期有效」)→ 行内弹出日期/时间编辑器 → 保存后自动归位(改到明天,明天显示在待办而非提醒列表)。

### 2. 日期与视图(活跃窗口)

- **活跃窗口**:一条待办从**添加当天起,到截止日期当天止,每天都显示在「今日待办」**;过了截止日仍未完成,转入底部「提醒列表」。
- **长期有效**:新增时日期、时间都不填 → 待办没有截止日,一直显示在每日待办里,直到完成。
- **历史浏览**:点击顶栏日期按钮 → 日历选择任意日期 → 查看「该日待办 / 该日已完成 + 提醒列表(累计)」;选中今天会自动回到今日视图(「◀ 返回今天」按钮随之显隐)。

### 3. 界面布局

- **三区结构(自上而下)**:
  1. **该日待办**(当天活跃的未完成待办,按紧急程度 → 截止时间排序);
  2. **该日已完成**(当天完成的记录,含完成时间);
  3. **提醒列表**(截止日早于查看日的未完成待办,**跨日期累计**;默认折叠在底部,点标题展开/收起,避免遮挡每日待办)。
- **布局切换(右上角按钮)**:上下(待办在上、已完成在下)⇄ 左右(两列并排、各自独立滚动、按更长一列撑满高度)两种布局,选择会记住。
- **外观**:整体透明度 30%–100% 可调;窗口尺寸可调(设置里保存)。

### 4. 贴边折叠

- 拖动窗口使其边缘**越过/重叠屏幕边缘** → 自动收纳成 **24×24 的应用图标**贴在屏幕边缘(四方向均可)。
- 点击小图标 → 在贴边位置展开原尺寸窗口;按住小图标可沿该边拖动位置。
- 也支持点右上角 ▣ 按钮手动折叠。

### 5. 邮件提醒

- 配置 SMTP(支持 QQ 邮箱等:账号/授权码/收件人/端口)。
- **立即推送一次**:手动发送当前汇总(仅需账号/授权码/收件人完整,无需勾选启用)。
- **测试发送**:发送测试邮件验证配置。
- **定时推送**:**每天** 或 **每周指定星期几**(一~日)+ 指定时间(如每周一 09:00)。
  - 周推只在**约定的星期**触发;本周已推过不会重复;周一没运行也不会顺延到周二。
- 邮件内容:⚠ 提醒(过期/临期)+ 📌 待办中 + ✔ 已完成 三部分,含紧急程度星级。

### 6. 数据管理

- **本地存储**:所有数据实时保存在 `todos.json`。
- **保存可靠性(三重保险)**:原子写入(先写临时文件再替换)+ 失败自动重试 3 次 + 每次启动自动备份 `.bak`。
- **导出 / 导入**:设置 → 导出待办备份(JSON)/ 导入待办备份。
- **打开数据目录**:设置 → 一键打开 `%APPDATA%\TodoBar`。

## 四、注意事项

1. **不要在应用运行时用编辑器打开 `todos.json`**(会锁文件,导致保存失败 EPERM);查看数据用设置里的「打开数据目录」。
2. 应用依赖 `node_modules` 下的 Electron;换机器或重装后需重新 `npm install`。
3. 无控制台环境(GUI 启动)下 `console.*` 会抛 EPIPE,错误统一写入 `error.log`,请从那里排查。
4. 建议定期用「导出备份」留底(启动备份 `.bak` 仅保留最近一次)。
